# XM Power Kit V7 上位机

配套固件：`UserCode/Task/APP/SerialCoreTask/`（协议 v2）。
USB CDC 与蓝牙（USART3）两条链路共用同一套协议，上位机在 Windows 上看到的都是 COM 口。

## 运行

```bash
pip install -r requirements.txt
python main.py
```

目录里已带打包好的单文件 `上位机.exe`（约 37 MB，双击即用，无需装 Python）。
改了代码后重新打包：

```bash
pip install pyinstaller
pyinstaller main.spec
# 产物：dist/上位机.exe
```

无硬件自检（验证协议编解码、参数、文件读写逻辑）：

```bash
python selftest.py
```

## 界面

| 页签 | 内容 |
| --- | --- |
| 参数配置 | 5 个大类、18 个分组，共 58 个参数；可读当前值/默认值，修改后统一写入；表头「新值」留空表示不修改 |
| 文件管理 | 浏览设备外部 Flash 上的 FATFS（类似资源管理器）；**拖拽上传**、上传文件夹、**多选批量下载/删除**、重命名、新建文件夹、右键菜单；显示容量与传输进度，可取消 |
| 固件升级 | 选择 `XM_Power_Kit.bin`（自动识别版本/CRC）→ 写入设备并安装；可一键回滚到上一版本。设备停在 bootloader 时自动切到「维护模式」，按钮变成「写入并安装」 |
| 设备信息 | 固件版本、协议版本、参数数量、Flash 容量、蓝牙波特率设置、刷新字库缓存、重启设备 |

连接后会自动读取一次当前参数与根目录。

界面随窗口大小整体缩放：字号、内边距、表格行高、列宽、导航宽度同步变化（0.80×～2.00×，
基准 1180×760），高分屏（4K / 系统缩放 150% 以上）自动跟随系统缩放，不会出现界面过小。

### 文件管理

- **拖拽上传**：把资源管理器里的文件或文件夹直接拖到列表里松手即可传当前目录；文件夹会按原结构
  在设备上建好目录再逐个上传（表头路径框会高亮提示"松开鼠标即可上传到此处"）。拖拽期间进度条、
  取消按钮、容量刷新都和在按钮上传时一样；
- **上传文件 / 上传文件夹**：不方便拖拽时用按钮，文件夹同样是递归上传；
- **批量下载**：按住 Ctrl/Shift 多选（可混合文件和文件夹）→「下载」→ 选一个本地目录，
  文件和文件夹会**按远端结构镜像保存**（`/font/sub/a.bin` → `<你选的目录>/font/sub/a.bin` 的相对结构）。
  进度按总字节推进，单个文件失败不会中断整批，结束后状态栏给出"已下载 N 个文件，共 X MB"；
- **批量删除**：多选后「删除」，确认框会列出"几个文件夹、几个文件（共多大）"，**不可恢复**；
  文件夹是递归删除的（先删里面的文件，再由深到浅删目录，因为设备端 `f_unlink` 不允许删非空目录）；
- **右键菜单**：打开 / 下载到… / 上传文件 / 上传文件夹 / 新建文件夹 / 重命名 / 删除 / 刷新；
- 双击文件夹进入、双击文件直接选目录下载；右键与多选都支持键盘操作（Ctrl+A 全选）。

设备端每个文件都要 open/close 一次（FATFS 扇区 4 KB），所以上传字库这类小文件每个约 45 ms/432 字节，
17 个字库约 30 秒；数量多时优先用拖拽/文件夹上传一次排队，中途可随时取消。

### 更新字库的流程

1. 文件管理页进入 `/font`（没有就新建）；
2. 「上传文件」选择 `.bin` 字模（如 `NotoMono10x14.bin`、`Mono5x7.bin`），或者直接把整个字库文件夹拖进来；
3. 回到设备信息页点「刷新字库缓存」——手动绘制的界面立即使用新字模；
4. LVGL 界面的字体是启动时 `lv_font_load` 加载的，需点「重启设备」才生效。

bootloader 自带的界面字库已经编译进固件，第一次开机由它自己写到 `0:/font/bootloader/boot.bin`，
不需要手动上传（要换字时重新跑 `Bootloader/tools/gen_boot_font.py` 再重新编译 bootloader 即可）。

### 固件升级（OTA）

升级包 = 80 字节包头 + 裸镜像（`.bin`）。包头字段：magic `"XMK7OTA1"`、版本串（32B）、镜像大小、镜像 CRC32、
包头 CRC32、目标地址（0x08010000）、构建日期（8B）、机型（16B）。

流程：

1. 编译固件，得到 `build/Release/XM_Power_Kit.bin`（CMake 的 POST_BUILD 会自动生成 `.bin` 和 `.hex`）；
2. 「固件升级」页 →「选择文件」→ 自动读出镜像里的版本串（就是 `SYS_VERSION_CODE`）并算出 CRC32；
3. 点「开始升级」：`OTA_BEGIN` 写包头 → `OTA_DATA` 分块传镜像（432 字节/块）→ `OTA_COMMIT` 校验并让设备重启；
   包头在**点按钮的那一刻**按磁盘上现在的文件重新算一遍，所以中途重新编译过也不会出现“包头和镜像对不上”；
4. 设备重启后进入 bootloader：校验包 CRC → 擦除应用分区 → 写入 → 回读校验 → 跳转新固件，屏幕上显示进度；
5. 新固件第一次启动时写 `BOOTOK.BIN` 确认，bootloader 从此认为本次升级成功。

回滚：

- 提交升级前，应用会把**当前正在运行的镜像**快照成 `0:/ota/PREV.BIN`，这就是回滚源（也就是“上一版本”）；
- 新固件连续 3 次启动失败（没写 BOOTOK）→ bootloader 自动用 `PREV.BIN` 刷回；
- 也可以手动点「回滚到上一版本」，设备重启后 bootloader 直接用 `PREV.BIN` 覆盖；
- 升级成功后 `PREV.BIN` 会保留下来，所以“退回上一版”在任何时候都可用；再升一次级它会更新成新的上一版。

### 维护模式（设备停在 bootloader）

设备屏幕一直停在「设备初始化 / 自检未通过」界面时，bootloader 会常驻并打开 USB CDC。此时用本上位机连接：

- 连接后自动切到「固件升级」页，按钮显示为「写入并安装」，参数配置页不可用（bootloader 没有参数与蓝牙）；
- 「写入并安装」会把镜像打包成 `FW.BIN` 传到 `0:/ota/FW.BIN`，写完后先 `FS_STAT` + 回读文件头尾核对
  是否完整，再发 `OTA_APPLY` 让设备立刻搬运安装，装上以后重启就进主程序——新板子首次安装和刷砖恢复
  都走这一条路，**不再需要手工传文件**；
- 上传不完整或包头对不上时，会直接提示具体原因（设备端文件长度不对 / 包头非法 / 镜像 CRC 与包头不符 ...），
  而不是笼统的“校验失败”；
- 「文件管理」页照常可用，可以往设备上传字库、图片等文件；
- 维护模式只走 USB（bootloader 不初始化蓝牙）。

外部 Flash 上的 OTA 文件：`0:/ota/FW.BIN`（待安装包，装完由 bootloader 删除）、`PREV.BIN`（上一版本快照）、
`BOOTOK.BIN`（启动成功标记）、`REQ.BIN`（应用写给 bootloader 的请求，含令牌防止重复执行）。

不想用「固件升级」页时，用「文件管理」把裸的 `XM_Power_Kit.bin`（或打包好的 `FW.BIN`）直接拷进 `/ota`
也行：bootloader 上电发现应用区无效时会自己扫描 `/ota` 里第一个 `.BIN` 并安装（裸镜像没有包头，
长度与 CRC 现场算，版本串从镜像里嗅探）。

注意事项：

- 升级期间不要断电；上传中断只会留下不完整的 `FW.BIN`，没有 `REQ.BIN` 的设备照常启动旧固件；
- 内部 Flash 分区：`0x08000000`+48KB = bootloader，`0x0800C000`+16KB = OTA 状态记录，`0x08010000`+448KB = 应用；
- 首次使用需要先用 ST-Link 把 `build/Release/Bootloader/XM_Power_Kit_Boot.hex` 烧到 `0x08000000`（只需一次）；
  之后新板子直接上电即可，bootloader 会现场格式化外部 Flash、建目录、写字库与参数文件，然后停在维护界面等上位机装固件；
- bootloader 界面字库已编译进固件（`Bootloader/boot_font.bin` → `.rodata`），不依赖外部文件；
  外部 `0:/font/bootloader/boot.bin` 存在时优先用它，方便换字体。

### 蓝牙

- 固件默认 115200 8N1（`USART3`，PB10/PB11）；
- 蓝牙模块的波特率必须与设备一致，不一致时先在「设备信息」页改设备端波特率（建议用 USB 连接改，改完重新连接蓝牙）；
- 设备端会把波特率保存在外部 Flash 的 `0:/btcfg.bin`，断电不丢。

## 协议

```
A5 5A | LEN_L LEN_H | CMD | SEQ | DATA[LEN] | CRC_L CRC_H
```

- `LEN`：负载长度（0~512，小端）
- `CRC16`：CCITT-FALSE（poly 0x1021，初值 0xFFFF），覆盖 `LEN` 到 `DATA` 末尾
- 升级包里的 CRC32 是标准 CRC-32（多项式 0xEDB88320，初值/结果取反，与 `zlib.crc32` 相同）
- 应答：`CMD`/`SEQ` 原样返回，`DATA[0]` 为状态码（0 = 成功），`DATA[1..]` 为数据

| CMD | 名称 | 请求 | 应答 |
| --- | --- | --- | --- |
| 0x01 | SYS_INFO | — | proto, 固件版本串, 参数个数, 参数字节数, 特性位（bit0 USB / bit1 蓝牙 / bit2 文件 / bit3 OTA / bit4 维护模式）, 蓝牙波特率, 总容量, 剩余容量 |
| 0x02 | SYS_REBOOT | — | — |
| 0x03 | SYS_BT_BAUD | u32 波特率 | — |
| 0x10 | PARAM_GET | u8 kind（0 当前 / 1 默认） | 232 字节参数 |
| 0x11 | PARAM_SET | 232 字节参数 | — |
| 0x20 | FS_LIST | len+path, u16 start, u8 max | count, u16 next（0xFFFF 结束）, 条目 |
| 0x21 | FS_READ | len+path, u32 offset, u16 len | u16 长度 + 数据 |
| 0x22 | FS_WRITE | len+path, u32 offset, u16 len + 数据 | u16 已写字节数 |
| 0x23 | FS_DELETE | len+path | — |
| 0x24 | FS_RENAME | len+old, len+new | — |
| 0x25 | FS_INFO | — | u32 总 KB, u32 剩余 KB |
| 0x26 | FS_MKDIR | len+path | — |
| 0x27 | FS_STAT | len+path | u8 属性, u32 大小 |
| 0x28 | FS_SYNC | — | — |
| 0x30 | OTA_INFO | — | flags, 上传中, 应用占用, PREV 版本/大小, FW 版本/大小/CRC, 失败次数, 状态 |
| 0x31 | OTA_BEGIN | 80 字节包头 | u32 已写（0） |
| 0x32 | OTA_DATA | u32 包内偏移 + 数据 | u32 累计已写镜像字节数 |
| 0x33 | OTA_COMMIT | — | —（设备随后重启） |
| 0x34 | OTA_ABORT | — | — |
| 0x35 | OTA_ROLLBACK | — | —（设备随后重启） |
| 0x36 | OTA_APPLY | — | —（维护模式：把 `/ota/FW.BIN` 立刻写进内部 Flash，设备随后重启） |

状态码：0 成功、1 参数错误、2 文件系统错误（附带 FRESULT）、3 不存在、4 数据过长、5 忙、6 不支持、7 校验失败。

单次文件读写数据量上限 432 字节（受 512 字节负载限制），大文件由上位机按偏移分块传输。
